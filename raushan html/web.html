Web Development

What is Web Development?

Web development is the process of creating, building, and maintaining websites and web applications that run online via browsers.

It involves a mix of front-end (user interface), back-end (server-side logic), and database management to ensure functionality, interactivity, and performance.

Web Browser

A web browser is a software application used to access, retrieve, and display information from the World Wide Web, including websites, images, and videos. It acts as an interface between the user and the web server, interpreting HTML code to render web pages. Popular examples include Google Chrome, Safari, Firefox, and Microsoft Edge.

How a Web Browser Works

When you type a URL like https://www.google.com and hit Enter, the browser goes through a high-speed process to deliver the page to your screen.

1. The DNS Lookup (Finding the Address)

Computers don't understand names like "https://www.google.com/search?q=google.com"; they understand numbers called IP Addresses (e.g., 142.250.190.46).

The browser contacts a DNS (Domain Name System) server.

It asks: "What is the IP address for this name?" Once it gets the address, it knows exactly which server in the world to talk to.

2. The Request (Sending the Letter)

The browser sends an HTTP/HTTPS Request to that server. Think of this as a formal letter saying: "Hello, I would like to see the home page files for this website, please."

3. The Response (Receiving the Raw Material)

The server sends back a Response. This usually includes:

HTML: The structure (the text and skeleton).

CSS: The style (colors and fonts).

JavaScript: The interactivity (buttons and animations).

4. Parsing & Rendering (Building the Page)

This is where the magic happens inside the Browser Engine. The browser reads the code and builds two internal maps:

DOM (Document Object Model):A tree structure of all the HTML elements.

CSSOM (CSS Object Model):A map of how those elements should look.

5. The Final Paint

The browser combines the DOM and CSSOM to create a Render Tree. It calculates exactly where every pixel should go on your screen (Layout) and then literally "paints" the colors, text, and images onto your display.

Browser Engine

The Browser Engine is the invisible powerhouse of a web browser. If the browser is a car, the User Interface (the address bar and buttons) is the dashboard, and the Browser Engine is the actual motor under the hood that makes the car move.

It acts as the primary coordinator between the User Interface (what you click) and the Rendering Engine (what you see).

What Exactly Does a Browser Engine Do?

    The Browser Engine manages the high-level logic of the browser. Its main job is to handle:

  • User Inputs: When you click "Back" or "Refresh," the engine tells the renderer what to do.

  • Data Flow:It manages the communication between the browser’s UI and the rendering engine that draws the pixels.

  • Security & Storage:It oversees things like cookies, local storage, and the security rules that keep websites from stealing your data.

How it Works: The Process

To understand how it works, you have to see where it sits in the "stack." It follows a specific flow:

  • The Trigger:You enter a URL. The Browser Engine tells the networking layer to fetch the data.

  • The Hand-off:Once the HTML/CSS files arrive, the Browser Engine hands them to the Rendering Engine.

  • Construction:The Rendering Engine builds the DOM Tree (the structure) and the CSSOM Tree (the styles).

  • Layout & Painting:The engine calculates the geometry (where things go) and "paints" the screen.

  • Interactivity:When you click a button, the Browser Engine detects that input and triggers the JavaScript Engine (like V8) to run the code.

    Client-Server Model

    The client-server model is a distributed application structure in web development where a user's device (client) sends requests for resources or data to a centralized computer (server), which processes the request and sends back a response.

    The client handles the user interface (frontend), while the server handles data management and business logic (backend).

    Key Components

  • Client (Requester): The end-user application, such as a web browser (Chrome, Firefox) or mobile app, which initiates interaction by requesting data, files, or services.
  • Server (Provider): A computer, system, or application (e.g., Apache, Nginx) that listens for incoming client requests, processes them, and returns the requested resources.
  • Network/Protocol: The communication channel (often the Internet) using protocols such as HTTP/HTTPS to transport requests and responses.

    • Request-Response Cycle

  • Request: A user clicks a link (client) which triggers an HTTP request, often sent to a server.
  • Processing: The server receives the request, processes it, retrieves necessary data from a database, or runs backend code.
  • Response: The server sends back the requested material, such as HTML/CSS/JS files or API data (JSON), which the browser renders for the user.

    • Example:

    Web Browsing: Your browser (client) asks for a webpage from a web server.

    Email: Outlook or Gmail (client) asks for new messages from an email server.

    URL (Uniform Resource Locator)

    A URL (Uniform Resource Locator), often called a web address, is a unique string of characters used to locate a specific resource—such as a webpage, image, or file—on the internet.

    It acts as the address, specifying the protocol (like HTTPS) and the location of the resource, allowing browsers to find it.

    Key Aspects of a URL

  • Web Address: It is what you type into the browser address bar to visit a site.
  • Structure: It typically includes the protocol (https://), the domain name (e.g., www.example.com), and the file path (e.g., /page).
  • Unique Identifier: Every page on the internet has a unique URL, ensuring it can be found.
  • Components:

    • Protocol: Defines how the data is transferred (e.g., http, https, ftp).

    Domain Name: The web address of the server (e.g., google.com).

    Path: Specifies the specific page or file on the server.

    Common URL Parts Example:

    https://www.example.com/folder/page.html

    Protocol: https

    Domain: www.example.com
